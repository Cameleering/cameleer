# Cameleer 0.8.0: gRPC and HTTP/2 on simoom 0.2.0, asynchronous routing

<!-- GitHub Release body for v0.8.0. The full list of changes is the 0.8.0 section of CHANGELOG.md. -->

0.7.0 moved gRPC and HTTP/2 onto [simoom](https://crates.io/crates/simoom). 0.8.0 makes that path fast: the gRPC
server runs its calls on a pool of threads, the event loops start at once, unary calls are cheaper, and simoom 0.2.0
batches replies. Routes that call the `http` producer from a `platform-http` route now answer from tasks.

This release has **behaviour changes** (listed under [Upgrading](#upgrading)); read them before you pull.

## What's new

- **gRPC unary calls.** 94,400 calls/s at 64 concurrent calls and 106,200 at 256 on 4-vCPU machines (cameleer-bench's
  load generator), against about 8,300 and 8,000 for 0.7.0, with 24 against 270 microseconds of server CPU per call,
  a p99 of 1.2 against 14.8 ms and 9.2 against 13.6 MB of peak memory; nghttp2's `h2load` drove the same server to
  129,000 to 135,000 calls/s. 0.7.0 does not have the thread pool for calls, so the ratio (11x to 13x) contains it; the
  pool alone was measured at 3.6x to 3.9x, and the other changes were not measured one by one.
- **HTTP/2 is not slower than HTTP/1.1.** The 0.51x reported on 2026-11-18 was mostly the benchmark's own HTTP/2
  client. `rest-json` over HTTP/2 equals HTTP/1.1 (1.00x) and `h2load` shows HTTP/2 at 1.5x to 1.6x the HTTP/1.1 rate.
- **Asynchronous routing, on by default.** A `platform-http` route that calls the `http` producer runs as a task and
  no longer holds a server thread while it waits; `maxInflightRequests` bounds it. Measured on one WSL2 machine only
  (2.2x to 2.9x requests per second for a proxy route), not on cloud machines.
- **simoom 0.2.0** and cheaper header handling (headers are kept sorted; iteration order is unchanged).
- **Benchmarks re-measured on 0.8.0** in one session: 1.8x to 15x the throughput of Apache Camel on the JVM, p99 lower
  in every scenario, MCP tool calls 2.06x Camel's `camel-mcp-server` and 19.9x the MCP TypeScript SDK. Against 0.7.0,
  plain HTTP and the JSON REST route are unchanged, and MCP is 0.96x to 0.98x (probably a real 2% to 4% slowdown; the
  cause was not isolated).

## Upgrading

- **The event loops of the HTTP and gRPC servers start at once**, one per CPU. A route is ready about 0.3 to 0.5 ms
  later (3.0 ms) and an idle server uses 0.3 to 0.5 MB more. `CAMEL_SERVER_LAZY_LOOPS=true` restores the lazy start
  (it stays lazy on AWS Lambda).
- **Asynchronous routing.** `CAMEL_ASYNC_ROUTING=false` keeps every route synchronous. A route answers `503` with
  `Retry-After: 1` beyond `maxInflightRequests` (default 10,000).
- Nothing else breaks.

## Not measured

Asynchronous routing on cloud machines, `h2load` over TLS, gRPC streaming, the gRPC client, Windows.
