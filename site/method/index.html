How to measure, so the numbers hold up

What we measure, how we measure it, what counts as a fair baseline, a ten-point check to run before each release, and the one-page report every ledger row links to. Use it on any software, in any language.

No claim without a number.

What counts as a fair baseline

Do

  • Compare with the version most people run today, with the exact version, runtime and flags written down.
  • Include the strongest variant of the baseline too, not only the easy one. Cameleer is compared with Apache Camel on the JVM and on Quarkus native.
  • Run both sides on identical machines, swapping roles between them, with the load generator on its own machine.
  • Run each scenario more than once and say how the figures were combined.
  • Round against yourself: your times and memory up, your ratios down.

Don't

  • Compare a tuned build with a default one, or a warm run with a cold one.
  • Quote the best ratio without the worst ("up to 54x" without "4.8x").
  • Leave out the scenarios you lose.
  • Present a target in the same style as a result.
  • Borrow one project's numbers for another.

The water check: ten questions before each release

Do we know each number, and did any of them get worse? Keep the answers in the repository, where the team sees them.

  1. Cold start time
  2. Memory when idle
  3. Peak memory under load
  4. Binary or image size
  5. Threads alive when idle
  6. p99 latency at the expected load
  7. CPU per request
  8. Number of dependencies
  9. Time a user waits behind a loader or spinner
  10. Is each result written down, with the date and the machine?

Cameleered or Cameleering: the two labels

"Cameleered"

A project may say it has been cameleered when all of these hold:

  • a before-and-after comparison against a named, current baseline version;
  • both sides on the same hardware;
  • a script anyone can rerun, and the raw results;
  • the losses disclosed;
  • measured within the last 12 months.

"Cameleering"

Work in progress: the baseline may be published and targets set, but nothing is measured yet. A cameleering project shows its targets as targets and no results. A project that has not started is listed as planned, with neither label.

The labels never carry another project's name or trademark, and they say nothing about the projects they are compared with beyond the measured numbers.
