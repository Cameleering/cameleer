Apache Camel in Rust: the options, and what has been measured

If you want Apache Camel's routing model without the JVM, there are three Rust projects to look at and one do-it-yourself path. They differ in one question that decides a migration: do your existing Camel routes run unchanged? This page compares them on facts from each project's own repository, and shows the one benchmark against Apache Camel that has been published.

Cameleer is one of the options, so read this as a vendor's comparison. Facts about other projects come from their repositories and crates.io pages, linked in the sources. Corrections are welcome as a GitHub issue.

How to choose

You have Camel routes already

  • Run them with cameleer validate routes/ first: it loads every file, resolves every endpoint URI against the real components and lists what is missing, without starting anything.
  • YAML and XML routes run unchanged with cameleer run; Java DSL routes, beans and custom components are rewritten in Rust. The migration guide lists what differs.
  • Check the long tail: Apache Camel has 300+ components, Cameleer about 230. The component index shows which exist.

You are starting fresh in Rust

  • If your team thinks in Tower services and wants routes as Rust code first, rust-camel is designed for that.
  • If you need two or three protocols and no routing language, a library such as rust-integration-services, or your own tokio service, is less to learn.
  • If you want Camel's patterns, YAML that a non-Rust team can read, and published numbers, start with Cameleer's getting started.

Common questions

Is there an Apache Camel alternative written in Rust?

Yes. Cameleer reimplements Apache Camel in Rust and runs Camel's YAML and XML routes unchanged as one native binary with about 230 components. rust-camel offers Camel-style routing built on Tower middleware and is pre-release. rust-integration-services is a smaller integration library that is not modelled on Camel.

Which one runs my existing Camel routes?

Cameleer, for routes written in Camel's YAML or XML DSL: the endpoint URIs, EIPs, Simple expressions and headers carry over. Routes written in Camel's Java DSL, and Java beans or custom components, have to be rewritten in Rust. rust-camel says it is not a drop-in replacement.

How much faster is Camel in Rust?

Cameleer was measured against Apache Camel 4.23 on Java 21 on identical cloud machines: 3 ms to start against 1.1 s, 4.8 to 54 times less peak memory, and 1.7 to 8.7 times the throughput, with one scenario where its p99 latency was higher. No published benchmark of the other Rust projects against Camel was found.

Is Cameleer the same project as rust-camel?

No. They are independent projects by different authors. rust-camel publishes the camel-* crates on crates.io; Cameleer publishes the cameleer-* crates. Neither is part of the Apache Software Foundation.

Is Camel on Quarkus native an alternative?

For startup time, yes: it started in 30 ms in the same benchmark, against 1.1 s on the JVM. It keeps Java and Camel's full component catalogue, but it had the lowest throughput of the three runtimes measured, because native images have no JIT compiler.
