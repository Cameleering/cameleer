A real job: refund a damaged order across four systems

A customer writes: “My order EU-4411 arrived broken. I want my money back.” Resolving it means reading the order, refunding it, creating a return label and emailing the customer. Rules: delivered orders only, the refund is the order total, refunds over 200 need a person.

Direct: the model orchestrates

  • Four tools: get_order, issue_refund, create_return_label, send_email.
  • A good run is 4 tool calls and 5 model turns, each re-sending the whole conversation.
  • The refund amount is whatever the model read or typed.
  • A retry after a timeout refunds twice. A carrier outage after the refund leaves money gone and no label.

Through Cameleer: the model decides, a route executes

  • One tool, resolve_damaged_order, with only what the conversation knows: request id, order id, reason.
  • The route validates the arguments, runs each request once, reads the total from the order and checks the rules.
  • Refund and label run as a saga: if the label fails, the refund is cancelled.
  • Retries with back-off, an audit entry, one clear answer to the model.

When a direct tool call is enough

Call the API directly when the call

  • only reads, like a search or a lookup, and a repeat does no harm;
  • is a single step with no other system to keep consistent;
  • is a prototype you will move behind a route before real users touch it.

Use a route as soon as a call

  • changes something: money, stock, messages, tickets;
  • spans several systems that must stay consistent;
  • needs a rule the model must not override, or an audit trail.

Common questions

Is Cameleer an AI agent framework?

Not primarily. An agent framework runs the model loop and decides which tool to call; Cameleer executes the tool: it is the action layer between the agent and your systems. For simple agents it also has an agent step that runs a model and its tools in a loop as one step of a route.

Does routing tool calls through Cameleer replace function calling?

No. The model still uses function calling; the tool it calls is a Cameleer route behind an HTTP endpoint, declared with the same JSON schema the route validates against.

Which models and agent frameworks does it work with?

Any that support function calling or tool use and can make an HTTP request: OpenAI, Anthropic, Google, AWS Bedrock and Azure OpenAI models, open models on Ollama or vLLM, and frameworks that let you define a tool as an HTTP call.

Does Cameleer speak MCP?

Yes. ai-tool routes are served to MCP clients over Streamable HTTP or stdio (cameleer run tools.camel.yaml --mcp), in the 2026-07-28 and 2025-11-25 protocol eras, with the same envelope: schema checks, deduplication, approvals, timeouts and audit. See routes as MCP tools. A tool can also stay a plain HTTP endpoint, which every framework with function calling can call. Apache Camel 4.22 ships an MCP server too; Cameleer uses its property names (comparison).

How is this different from a hosted tool catalog such as Composio or Arcade?

Those platforms give an agent many pre-built connectors with managed OAuth, hosted and priced per use. Cameleer is open source and self-hosted: a 20 MB container or a library, about 230 components, and the reliability around the call written as a tested route: schema validation, idempotency, retries, sagas, human approval, rate limits and an audit log. Use a catalog for breadth of SaaS actions; use Cameleer when the action changes money, stock or records and must run exactly once inside your own network.

What happens when an agent retries a tool call?

The route sees the same requestId and answers duplicate without executing anything again.

When is a direct tool call enough?

When the call only reads, is a single step with no other system to keep consistent, or is a prototype. Use a route as soon as a call changes something, spans several systems, needs a rule the model must not override, or must be audited.

Does an extra hop make tool calls slower?

A route adds microseconds to a call; a model turn takes hundreds of milliseconds to seconds. A multi-step job through one route saves model turns, so it is usually faster end to end.
