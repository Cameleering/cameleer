Apache Camel vs Cameleer

Cameleer runs Apache Camel's routes, EIPs and YAML DSL as one native binary. We ran the same routes on both, from in-memory routing to REST APIs, Kafka and PostgreSQL. Cameleer starts in milliseconds, runs in megabytes and moves more messages on the same CPUs.

What about Apache Camel on Quarkus native?

Compiling Camel ahead of time with Quarkus and GraalVM (Mandrel) removes most of the JVM's startup time and memory. It is the closest thing to Cameleer in the Java world, so we measured it too.

What native compilation gives Camel

  • Startup in tens of milliseconds instead of about a second.
  • Much less memory than on the JVM.
  • One executable to ship.

What it costs

  • No JIT compiler: throughput is lower than the same routes on the JVM.
  • Long native builds and closed-world restrictions on reflection and dynamic features.
  • Cameleer still starts faster, uses less memory and has more throughput than both.

How we tested

Three identical cloud machines on one private network, default settings on every runtime, and the servers swapped halfway so neither side got the better machine.

Setup

  • Three DigitalOcean CPU-optimized droplets (c-4): 4 dedicated vCPUs (Intel Xeon Platinum 8168), 8 GB RAM, Ubuntu 24.04, region blr1.
  • Two servers take turns running each runtime; the third runs the HTTP load generator, Apache Kafka 4.3.2 and PostgreSQL 16.
  • Apache Camel 4.23.0 on Temurin 21.0.13. Apache Camel 4.22.1 on Quarkus 3.40.0, compiled with Mandrel 25.0.4.1. Cameleer 0.4.0, built with Rust 1.99.1.

Method

  • The same routes on every side, defined once per language from one specification.
  • 15 s warmup, then five timed 5-second iterations; the figure is the mean of both servers.
  • 64 concurrent HTTP keep-alive connections from the load machine; PostgreSQL pool of 16 on every side.
  • Default settings: no JVM flags, no GC or thread tuning. Peak memory and CPU from /usr/bin/time.

Common questions

Is Cameleer a drop-in replacement for Apache Camel?

For routes written in Camel's YAML or XML DSL with the components Cameleer provides, yes: the same endpoint URIs, EIPs, Simple expressions and headers. Routes that call Java beans or use the Java DSL need those parts rewritten, and a few Camel components have no Cameleer equivalent.

Was the JVM warmed up?

Yes. Every scenario runs 15 seconds of warmup before five timed 5-second iterations, on both sides, so the JIT compiler has finished its work before anything is measured.

Was Apache Camel tuned?

Both sides ran their default settings: no JVM flags, no thread pool or GC tuning, and the same connection pool size for PostgreSQL. The routes are identical on both sides.

What about Apache Camel on Quarkus native?

It is in the benchmark. Native compilation makes Camel start much faster and use less memory than on the JVM, but without a JIT compiler its throughput is lower than on the JVM. Cameleer is faster and smaller than both.

Can I run the benchmark myself?

Yes. The routes, the harness and the scripts that create the cloud machines are in the repository under scripts/cloud-bench; a full run costs about one US dollar of cloud time.

Run your Camel routes on Cameleer

Mount a Camel YAML route and run it. No JVM, no build.

docker run --rm -p 8080:8080 -v "$PWD:/routes:ro" cameleering/cameleer run /routes/hello-api.camel.yaml
