Cameleer / MCP

Model Context Protocol

Your integration routes, as reliable tools for AI agents

Cameleer serves routes as MCP tools to Claude, IDE assistants and agent frameworks. Every call is checked against a schema, runs once, waits for a person when it is risky, is cancelled when it is slow and lands in an audit log, whatever the model decides. Over stdio or Streamable HTTP, in both protocol eras, from a laptop to a serverless function or an edge gateway.

How it works

A tool is a route. The route does the work with any of Cameleer's about 230 components; the server does the rest on every call.

A tool, served

- route:
    from:
      uri: ai-tool:lookup_order
      parameters:
        description: Look up an order by id
        parameter.orderId: string
        parameter.orderId.required: true
        readOnlyHint: true
      steps:
        - setBody:
            simple: '{"orderId": "${header.orderId}", "status": "shipped"}'
cameleer run tools.camel.yaml --mcp          # http://localhost:8080/mcp
cameleer run tools.camel.yaml --mcp-stdio    # Claude Desktop starts it

On every call

  • Checked: JSON Schema 2020-12 on the arguments; unknown and camel* arguments dropped.
  • Run once: a retried call in the same conversation returns the first result.
  • Approved: destructive tools show the user a form, or wait for an operator.
  • Bounded: rate limits, circuit breakers, and a timeout that cancels the route.
  • Recorded: redaction of personal data, then a hash-chained audit record.
  • Pinned: a tool definition cannot change under your clients; a kill switch withdraws a tool.

Apache Camel's ai-tool, ai-resource and camel.server.mcp-* names work unchanged. Cameleer also imports other MCP servers' tools and serves them again, so one endpoint can front many. Reference: Cameleer MCP guide, MCP server, MCP client and gateway.

Common questions

What is Cameleer's MCP server?

It serves Cameleer routes (ai-tool, ai-resource and ai-prompt endpoints, with Apache Camel's option names) to MCP clients such as Claude Desktop, VS Code, Cursor and agent frameworks, over Streamable HTTP or stdio, in the 2026-07-28 and 2025-11-25 protocol eras. Every call goes through an envelope: schema checks, deduplication, approvals, rate limits, circuit breakers, a timeout that cancels the route, redaction and a hash-chained audit record.

How fast is it compared with Apache Camel's MCP server?

On three identical cloud machines with 4 dedicated vCPUs each and 64 connections, Cameleer served 41,620 tool calls per second in MCP sessions in 53 MB of memory, against 22,458 calls per second in 317 MB for Apache Camel 4.23's camel-mcp-server on the JVM and 1,536 calls per second in 214 MB for a server on the official MCP TypeScript SDK. Camel's p99 latency was lower (5.2 ms against 5.9 ms).

Does it work with Claude?

Yes. In a field test, 40 requests a shop's staff would type ran through Claude and the official MCP client against Cameleer's shop example: Claude Opus 5.5 completed 157 of 160 runs correctly in 2025-11-25 sessions and 39 of 40 in the stateless 2026-07-28 era, with 2.9 turns and 3.3 tool calls per request on average.

Where can it run?

As a subprocess of a desktop client over stdio, as a server, in Docker, Docker Compose and Kubernetes, on Cloud Run, Knative and Azure Container Apps, on AWS Lambda through a function URL, and on an edge gateway next to the devices its tools control.

Can it sit in front of other MCP servers?

Yes. Cameleer imports the tools of other MCP servers over HTTP or stdio, lets you choose which to expose, puts the same envelope on them (rate limits, caching, approvals, audit, pinned definitions) and serves them through one endpoint. See the gateway use case.

Try the shop in Claude Desktop

The shop example is 19 tools, three policies and two prompts in one YAML file. Run it over HTTP, or let Claude Desktop start it (configuration in the example's README).

git clone https://github.com/pmsudhi/cameleer && cd cameleer/examples/agents/mcp-shop
cameleer run shop.camel.yaml --properties application.properties
# or, with nothing installed but Docker:
docker run --rm -p 18190:18190 -v "$PWD:/routes:ro" pmsudhi/cameleer run /routes/shop.camel.yaml \
  --properties /routes/application.properties --prop acme.dir=/routes --prop camel.server.host=0.0.0.0
